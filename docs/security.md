# Security model and limits

## Current capability

The local coordinator detects npm/Bun, reads configured global-tool manifests and explicitly selected npm/pnpm/Bun project manifests/lockfiles, and queries eligible public npm versions. It also reads runtime support dates from endoflife.date and, unless the owner turns the lookup off in Settings, the release age, license, and provenance of public npm update candidates from deps.dev; the first request sends only a fixed product name, the second only a public package name and version. OSV known advisory checks remain limited to supported project dependencies. Windows registry/WinGet scanning has been removed. Private/custom registries, local/Git tools, unsupported release channels, and other ecosystems remain outside coverage. GitHub/GitLab selected repository scans and authenticated paired-PC evidence now have verified implementations; physical LAN/Tailscale deployment remains unverified. Empty, partial, failed, and unsupported checks are distinct outcomes.

The administrative coordinator stays on loopback. A separate opt-in HTTPS evidence listener has scoped pairing and revocation controls. Loopback limits network reachability; it does not make hostile local processes or browser-origin requests trustworthy.

## Trust boundaries

| Boundary                        | Required controls before the feature ships                                                                                                                        |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Browser/Electron → coordinator  | Validated request/response schemas, strict routes and methods, body limits, origin/host policy for browser requests, and authentication for sensitive operations. |
| Collector → coordinator         | Explicit pairing, authenticated TLS, per-device credentials, revocation, bounded payloads, replay/idempotency handling, and rate limits.                          |
| Repository/filesystem → scanner | Explicitly selected roots, validated paths, symlink/traversal handling, bounded file sizes and parse work, format validation, and no script execution.            |
| Coordinator → executable        | Allowlisted tool identity, argument arrays without shell interpolation, timeouts, bounded output, cancellation, and a controlled environment.                     |
| Coordinator → remote source     | Fixed/validated destinations, HTTPS, redirect policy, response limits, timeouts/backoff, and careful token scoping.                                               |
| Electron renderer → host        | Sandboxing, context isolation, Node integration disabled, narrow IPC if needed, navigation restrictions, and controlled external-link opening.                    |

LAN membership and Tailscale reachability are transport facts, not authorization. Hostnames and IP addresses are not device identities. Repository metadata, scanner output, and registry responses remain untrusted even when fetched over HTTPS.

File size alone does not bound parse work. pnpm lockfiles (at most 10 MiB) parse on a worker thread, which project removal or coordinator shutdown terminates. The YAML that pnpm writes parses in time linear in its size. Lockfiles using YAML anchors, aliases or collection keys, which pnpm never writes, are reported as unsupported, and repeated keys as malformed. Every parse is also limited to 30 seconds and a 1 GiB worker heap; a lockfile that exceeds either is reported as a failed check. Projects scan one at a time, so a hostile lockfile can delay other scans by up to 30 seconds at each scheduled rescan.

## Read-only background monitoring

This PC package updates are separate explicit desktop actions, offered in any desktop build. Windows hardware ran them live on October 3, before Wave 1, and again on October 11 (disposable roots, one package per manager); the update adapter has run real npm updates in a Linux container, while the Electron runner off Windows, Bun off Windows, and macOS and Linux hardware are unverified. Validated trusted-frame IPC accepts existing installation IDs and expected/target versions; fresh source/root/package checks reject changed, private, linked, unsupported, or stale targets. npm uses the observed prefix and Bun the observed global directory. The native runner locks each root, executes argument arrays without a shell, removes Node/Electron overrides, bounds runtime/output, cancels process trees, verifies installed metadata, and requests a rescan. Normal installer lifecycle/trust settings apply only to these owner-launched updates. Output is discarded and errors sanitized; no updater execution is exposed through HTTP, boot-host scheduling, or paired PCs. Update all sends at most 1,000 of the same validated requests in one IPC call; each is rechecked against the current coordinator snapshot before any runs, and they run sequentially under the same locks, bounds, and verification. See [update behavior](global-tool-updates.md).

Owner-authored Project actions are a separate, manual desktop capability. They run with the signed-in owner's privileges and can modify the checkout when launched. Saving/scanning never executes them. Trusted main-frame IPC validates schemas, selected project/action IDs, and the exact reviewed command; the native runner revalidates a canonical local directory and rejects provider-only/UNC targets. On Windows it uses an absolute allowlisted PowerShell executable with an encoded script; on macOS and Linux the owner's login shell from `/etc/shells` (or `/bin/sh`) receives the command as the single argument after `-l -c`, detached into its own process group. Both use argument arrays, a separate cwd, no shell interpolation of project metadata, hidden windows on Windows, bounded output, a deadline, and process-tree or process-group cancellation. The environment removes inherited Electron/Node override variables. Quit UI stops tracked commands without stopping monitoring.

Copyable upgrade commands are text for the owner's own terminal. Their package names, versions, and workspace paths come from lockfiles, so a command is built only from a strictly validated registry package name, an exact SemVer version, and a workspace path made of letters, digits, and `. _ / -`, plus spaces, `@ + ~`, and non-ASCII letters or digits inside double quotes. Any other character in a path yields no command (the menu offers the package name instead), because quoting does not protect it: cmd.exe re-parses the arguments of a `.cmd` shim such as `npm` or `pnpm`, so a quoted `&` still starts a second command. Paths that start with `-`, hold a blank segment or one ending in a dot (`..`, and a trailing `...` that pnpm reads as a selector) also get none. Aliases, non-registry sources, transitive dependencies, unchecked candidates, and This PC results that are unverified or in flux get none either, and an advisory is offered only an update that reaches its listed fixed version, none when no fixed version is listed. The desktop opens only validated HTTPS pages in the default browser: OSV advisories, npm package pages, GitHub/GitLab repository pages whose path segments start with a letter or digit, and its own release page. Project-wide upgrade commands combine packages only through the same validated name, exact version, and quotable path rules, one workspace and dependency type per command. The desktop grants its own pages one browser permission, plain-text clipboard writes for Copy buttons; reading the clipboard and every other permission stay denied.

There is no command execution HTTP or paired-PC API. Shared evidence omits action definitions; output remains transient native memory and routine logs exclude command text/output. Commands are stored in owner-local SQLite without secret encryption, so avoid embedded credentials. The implementation follows [Node 24.19 child-process APIs](https://nodejs.org/download/release/v24.19.0/docs/api/child_process.html), [Electron sender validation](https://www.electronjs.org/docs/latest/tutorial/security#17-validate-the-sender-of-all-ipc-messages), [PowerShell EncodedCommand](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_powershell_exe?view=powershell-5.1), and [Windows process-tree termination](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/taskkill). See [command behavior and limits](project-settings.md).

Open Versionstead at login is a separate owner-session desktop switch. Trusted main-frame IPC accepts only a boolean and then writes or removes one entry for this app in the signed-in owner's own account: Electron's Run value on Windows, a LaunchAgent on macOS, or an XDG autostart file on Linux. Paths an entry cannot carry safely are refused, nothing runs when the switch changes, and no HTTP, paired-PC or background-host path reaches it.

Background work may inspect selected files and query documented metadata interfaces. It must not install dependencies, restore a project, execute lifecycle/build scripts, upgrade applications, modify lockfiles, or run arbitrary commands from repository configuration.

Some ecosystem commands have side effects. For example, `.NET package list` behavior depends on SDK version and may restore by default. Prefer existing resolved data; explicitly suppress restore only where that behavior is supported and verified. Missing data is an incomplete scan.

Local owner-session `outdated` checks run verified installed npm/pnpm CLI files through Node, or the real Bun executable, without a shell. Version-manager shims (mise, asdf, Volta) read the directory they run in and may install what it pins, so no launcher runs inside a project: npm and pnpm launchers are only located to find their scripts, and Bun is asked once, from an empty private directory, which executable it resolves to. That question, the desktop's equivalent for Node, and every other command that a scan or tool discovery runs set mise's `auto_install`, `exec_auto_install`, and `not_found_auto_install` to false, so a mise shim does not install a configured but missing version. mise installs a tool declared `lazy = true` the first time its shim runs, whatever those switches say, so a mise shim is never run: a Bun found only as a mise shim is reported as unavailable, the desktop starts its coordinator with a Node from mise's installed versions, and development tools (Git, GitHub CLI, GitLab CLI, Tailscale, SSH) come only from real files. Other version managers get no such switch ([limits](package-manager-checks.md)). Repository PATH entries and unverified CLI versions are skipped. Only eligible public direct names are passed as arguments. Each invocation has a 30-second deadline and 4 MiB output bound; stderr, malformed output, and unavailable records fall back without persisting raw output or paths. Inherited Node/Corepack/npm/pnpm overrides are cleared; npm user/global config files are isolated. pnpm hooks and automatic manager downloads are disabled explicitly, and configuration-dependency plugins cause file/registry fallback before CLI initialization. Noninteractive hosts and provider API scans never execute these commands. Live CLI verification checks that fixture manifests/lockfiles and the repository-script marker stay unchanged. Private registry authentication remains outside this feature. See [behavior and limits](package-manager-checks.md).

Project dependency changes, commits, and pull requests remain separate future user actions. This PC's explicit Update now and Update all actions are implemented for supported global packages.

PC discovery selects installed npm/Bun executables from explicit absolute PATH entries and supported local fallback directories for Windows, macOS, and Linux. POSIX executables run under the name they were found by, since version-manager shims dispatch on it; a Node that is not the running coordinator is verified by running a bounded `-e` probe from an empty private directory, and its self-reported real path is used. On macOS, Apple's `/usr/bin/git` stub is not run until `xcode-select -p` succeeds. These macOS and Linux paths are checked only by platform-injected tests, a Linux container, and the macOS CI run at commit e4e3a53 (neither has Bun, and version-manager shims are simulated); native macOS behavior on Mac hardware is unverified. npm's validated CLI runs through Node with fixed global root/config commands; `.cmd` shell wrappers are never executed. Bun is asked for its version only by the same bounded `-e` probe, from an empty private directory; its exact global directory is resolved from supported configuration/environment defaults without executing `bun pm ls`. That listing command can create its global directory and climb to an unrelated parent manifest when the expected manifest is absent. Interactive discovery (a PC scan, Update now, and capturing sources for a background host) also runs one such bounded `-e` probe on the first `node` on the owner's PATH, from an empty private directory, to record its version for runtime lifecycle checks; only a valid SemVer version is recorded, and background scans use the value captured earlier. Commands run outside selected projects with argument arrays, timeouts, bounded output, and `NODE_OPTIONS` cleared. Package versions come from bounded installed manifests; package executables and lifecycle scripts never run. Canonical local roots and selected-file validation reject network shares, traversal, and escaping symlinks. The boot host reads owner-captured roots and Bun's single direct-dependency manifest; it grants no broad owner-profile or registry-credential access. Availability/version remains an owner-session observation after sign-out, separate from metadata access freshness.

Global lookup destinations are fixed to the public npm registry with HTTPS, rejected redirects, response limits, cancellation, and a scan budget. Public npm metadata and OSV advisory details are cached in coordinator memory only (metadata for at most 2,000 names, fresh for 30 minutes, then revalidated with the registry's own `ETag`, which is sent back only if it holds plain entity-tag characters), and public requests are retried once for 429, 503 or a failure before any response arrives, within the stage budget (a request that exceeds its 12-second timeout and a cancelled scan are not retried); a failed revalidation never serves stale data as current. Public registry classification, excluded configured scopes, private manifest flags, and local/Git/URL dependency requests prevent known private/local names from public queries. Unknown registry/configuration evidence is not public permission. Source configuration is authenticated, schema/path validated, and cannot change during PC work. Refresh it after changing routing; background scans cannot observe new owner settings while signed out. Credentialed registries and complex unsupported Bun configuration need explicit support before checks can become verified.

## Data and secrets

Collect the minimum metadata needed to explain findings: package identities/versions, selected project/device identity, source/channel, scan provenance, and advisory references. Source code does not need to leave a device for ordinary dependency scanning. Advisory queries can reveal package names and versions to the selected provider; describe that egress when the integration is introduced.

Do not log tokens, credential-bearing URLs, raw lockfiles, source files, or full local paths by default. Sanitize errors and external process output. The transient coordinator capability is encrypted using Windows DPAPI LocalMachine in a private runtime descriptor so the owner and LocalService can reconnect. Scoped filesystem ACLs are essential: any account able to read that encrypted file on the same machine can potentially decrypt it. It is not an external registry credential and is not stored in SQLite or process arguments. Non-Windows descriptors rely on owner-only file permissions; native desktop behavior there is unverified. On macOS and Linux, provider tokens, paired-PC tokens and the paired-PC private key are kept in the OS keychain — `/usr/bin/security` and the login keychain on macOS, `secret-tool` and the Secret Service (tested with GNOME Keyring; KWallet's Secret Service is untested) on Linux — under service `dev.versionstead` and a random account handle; SQLite keeps only a `keychain:v1:` reference. The secret travels on standard input, never in process arguments or logs; macOS refuses a credential too long for one `security -i` line (about 2,700 characters). A host whose keychain is missing, locked or unsupported says what is missing and never falls back to weaker storage. A keychain tool or DPAPI run that does not finish is reported as not answering, with a request to try again, and is never taken for a missing or unreadable credential. On Linux `secret-tool` is run only from `/usr/bin` or `/bin`, never found through PATH. It answers a locked keyring as it answers a missing item, so a credential read or deletion that finds nothing checks the keyring again and reports a locked one as locked, never as a lost credential or a completed deletion. Any process running as the owner can read these items: on macOS through `/usr/bin/security`, which the item trusts; on Linux through the unlocked Secret Service. A data directory created outside the Windows profile gets an owner, SYSTEM and Administrators access list, and if Windows will not apply it the desktop and the coordinator stop and say so rather than use the folder. Windows PowerShell in Constrained Language Mode is reported by name instead of timing out when monitoring starts, when a credential is stored and when a PC is paired; reading a credential that was saved earlier still reports only that it could not be unlocked.

`pnpm run access` deliberately prints that capability only on explicit owner request. The browser exchanges it for an HttpOnly, SameSite=Strict session cookie; Electron attaches a bearer capability in its native protocol handler. Host/origin checks, body/header limits, fixed API routes, and request/response schemas protect the loopback boundary. Restart rotates the capability and invalidates prior browser sessions. This does not protect against malicious processes already running as the owner or LocalService.

Public checks send eligible npm package identities and resolved versions to `api.osv.dev`; direct package names are queried from `registry.npmjs.org`. Source code, full local paths, lockfile contents, and registry credentials are not sent. Workspace/Git/local identities and private origins identified by selected-root `.npmrc` or lockfile URLs are excluded. User/global/ancestor/environment npm routing is not inspected; configure selected-root registry identity before scanning dependencies whose privacy depends on those settings. This ceiling is also reported in scan coverage. Direct dependency names whose update the installed package manager reported are also requested from `registry.npmjs.org` (the same abbreviated-metadata request as other version checks) to read deprecation messages and install-script flags. Deprecation messages are stored as plain text of at most 300 characters, with escape sequences and invisible or bidirectional characters removed, and are never rendered as HTML.

Runtime lifecycle checks send `GET https://endoflife.date/api/v1/products/{product}/` for the fixed products `nodejs`, `bun`, `electron`, and `pnpm` only; no version, project, path, or device detail is sent. Each product is requested at most once per 24 hours (an hour apart after a failure) over HTTPS with redirects rejected, a 12-second timeout, and a 1 MiB response limit; like other public requests, a connection failure, a 429 or a 503 is retried once. The response is schema-validated and cached in SQLite with its fetch time.

Release checks send `GET https://api.deps.dev/v3/systems/npm/packages/{name}/versions/{version}`: the public npm package name and candidate version of each update candidate that already qualifies for public npm registry checks, never private, local, Git, workspace, or unresolved identities, and nothing else. An answer with its publish time is cached by name and version (the newest 10,000), so such a candidate is requested once; a version deps.dev does not know yet, an answer without a publish time, and a malformed answer (including a publish time that is not an RFC 3339 time naming a real day) are not cached and are asked again on a later scan. Requests use HTTPS with redirects rejected, 12-second timeouts, a 1 MiB response limit, and schema validation; like other public requests, a connection failure, a 429 or a 503 is retried once. Settings › General › Use deps.dev for release age, license and provenance (on by default) turns these requests off; release age, license, and provenance then read as unknown. deps.dev use is subject to the Google API Terms of Service, which expressly permit caching (https://docs.deps.dev/api/v3/).

Local database files and backups require appropriate filesystem permissions. Document retention, deletion, export, and credential revocation when persistence and enrollment ship. A remote collector must not receive the coordinator’s repository credentials.

Exports are built in the window from the snapshot it holds and leave only through the owner's copy or save. They omit local folder, manifest, and lockfile paths, global tool locations, and this PC's name, but they do name projects, packages, versions, and provider repository addresses, so the owner should read one before sharing it. Markdown and CSV reduce untrusted text to one plain line; JSON keeps it whole but writes characters that hide or reorder text (control and format characters, line and paragraph separators) as Unicode escapes. Markdown escapes its syntax and writes only validated https addresses (an advisory, a repository) as links, which keeps advisory and deprecation text from adding Markdown links, images, HTML, or table cells; GitHub may still turn bare web addresses, email addresses, @handles, and issue numbers in that text into links. CSV and JSON carry an advisory address only when it is https. CSV quotes every cell, turns control characters such as tab, CR, and LF into spaces, and prefixes an apostrophe to a cell that starts with =, +, -, @, or a full-width variant (OWASP CSV injection).

## Meaning of vulnerability coverage

The initial intended scope is known dependency advisories, not a source-code audit, malware scan, or guarantee of safety. An absent advisory can mean no known match, unsupported identity, incomplete graph, stale data, or a failed lookup. Keep these outcomes distinct.

Use ecosystem/package identities and affected-version ranges. Installed desktop application names alone are insufficient for reliable CVE matching. Linux vendors backport fixes, so an old-looking upstream version is not by itself evidence of a vulnerable distribution package. Deduplicate advisory aliases while retaining each source’s evidence.

Use an explicit scanner version and report format coverage. Validate npm, Bun, NuGet, and Cargo behavior independently; support in an upstream tool does not mean support in Versionstead until the integration has been checked.

## Implementation gates

Before claiming a new boundary is supported, add focused checks for unauthorized or malformed input and the applicable failure cases. High-value cases include traversal/symlink escape, oversized inputs, subprocess timeout, offline lookup, revoked collector credentials, duplicate uploads, and interruption before a scan commits.

Before a public release, establish a license, a private vulnerability-reporting channel, dependency update policy, release signing, and a supported-platform matrix. This document is an implementation guide and capability limit, not a claim that a security audit has been completed.

## Implemented provider and paired-PC boundaries

On Windows, GitHub.com and GitLab.com tokens and outgoing PC credentials are encrypted with Windows DPAPI LocalMachine in SQLite; on macOS and Linux they live in the OS keychain (see Data and secrets). The paired-PC private key (a Node-generated P-256 key; earlier Windows hosts keep their PFX) uses the same protection. Scoped filesystem ACLs remain essential: DPAPI machine scope permits the background service to unlock credentials, and anyone who can read the protected database on the same machine may be able to decrypt them. Provider connection never enumerates into the scan queue: only owner-selected repository IDs/refs are scanned. CLI token import is an explicit interactive action; the signed-out host does not read an owner CLI credential store. Disconnect deletes the current protected credential (DPAPI blob or keychain item) while preserving evidence; an item that cannot be deleted while the keychain is locked stays behind. SQLite journal/backup retention can retain old encrypted blobs, so revoke the token with the provider when ending access.

Provider metadata/file requests use fixed HTTPS API hosts, reject redirects, have bounded responses and timeouts, and never execute fetched scripts. Every file request uses the commit resolved at scan start. Existing public npm/OSV classification still applies, including explicit unsupported/private coverage. Git status disables repository clean/process filters and fsmonitor, suppresses submodule checks, and clears inherited Git path overrides; a regression fixture configures executable filters and verifies that they never run.

PC sharing accepts private LAN/Tailscale IPv4 addresses, requires pinned TLS plus per-client bearer credentials, rejects browser-origin requests, and exposes no administrative API or arbitrary paths/commands. Pairing codes expire in five minutes, accept at most eight failed attempts, and are single-use. Clients validate the certificate before writing credential headers, then validate the device ID, response schema, and an unpredictable request nonce. Scan requests coalesce and are limited to once per ten seconds per client. Incoming JSON is limited to 4 KiB and received evidence to 16 MiB. The host allows 16 clients; this client supports eight connected PCs. Revocation immediately blocks new requests; an already completed read cannot be recalled. Removal attempts remote revocation, but an offline host requires the owner to revoke the client there too. The evidence endpoint reads an optional `X-Versionstead-Features` header, and a value that is not an exact marker of v10 or later reads as none; it only selects how much of the already shared evidence an authenticated client can read, never what stays on this PC.

The self-signed certificate expires after one year. A saved certificate that cannot be read or has expired is not replaced unasked: sharing stays off with a message after a restart, and turning Network access off and on creates a new certificate and tells the owner that paired PCs must pair again; a locked credential store never causes one, and a legacy PFX certificate cannot be dated, so its expiry goes unnoticed. Scheduled certificate rotation and a recovery UI, IPv6/DNS endpoints, central peer notification delivery, and physical two-PC/firewall/sign-out validation remain future work. TLS pinning prevents impersonation; it does not make an invitation from an untrusted source safe. Treat invitations as short-lived access secrets and exchange them through a trusted channel.

Pairing URLs put the encoded invitation in a fragment and validate it identically on the renderer and server. Separate host/code input cannot replace the invitation's endpoint or pin. Disabled environments retain evidence and protected credentials but stop polling and reject refresh/scan actions. Removing one still attempts remote revocation before forgetting its local credential.

Optional SSH forwarding runs only in an interactive owner session. The adapter reads at most 64 KiB/200 blocks of simple local SSH configuration as data; it never invokes `ssh -G` or evaluates Include/Match/proxy/executable directives. It passes validated host/user/ports and local key/known-host paths to the allowlisted OpenSSH client with an argument array, `-F none`, no remote command, loopback-only forwarding, strict host-key checks, batch authentication, and agent/X11 forwarding disabled. Native prompts and inherited Node/askpass configuration are disabled. Local key and known-host filenames containing SSH expansions, controls, quotes, or network-share paths are rejected. SSH stderr is discarded and bounded; connection attempts time out, and cancellation/disable/removal/shutdown terminate the tunnel.

The owner configures keys, an unlocked agent, and verified host keys separately. Versionstead stores no SSH passwords, private keys, or passphrases and does not install/start a remote SSH server or monitor. The HTTPS peer retains its original authority and certificate/device checks through the tunnel; credentials are sent only after its pin matches. This protects the Versionstead boundary independently of SSH host authentication. Real SSH authentication and physical remote networking remain acceptance tasks. Noninteractive hosts reject SSH transport and use authenticated LAN/Tailscale HTTPS instead.
