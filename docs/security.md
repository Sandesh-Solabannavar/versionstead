# Security model and limits

## Current capability

The local coordinator detects npm/Bun, reads configured global-tool manifests and explicitly selected npm/pnpm/Bun project manifests/lockfiles, and queries eligible public npm versions. OSV known advisory checks remain limited to supported project dependencies. Windows registry/WinGet scanning has been removed. Private/custom registries, local/Git tools, unsupported release channels, and other ecosystems remain outside coverage. GitHub/GitLab selected repository scans and authenticated paired-PC evidence now have verified implementations; physical LAN/Tailscale deployment remains unverified. Empty, partial, failed, and unsupported checks are distinct outcomes.

The administrative coordinator stays on loopback. A separate opt-in HTTPS evidence listener has scoped pairing and revocation controls. Loopback limits network reachability; it does not make hostile local processes or browser-origin requests trustworthy.

## Trust boundaries

| Boundary                        | Required controls before the feature ships                                                                                                                        |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Browser/Electron → coordinator  | Validated request/response schemas, strict routes and methods, body limits, origin/host policy for browser requests, and authentication for sensitive operations. |
| Collector → coordinator         | Explicit pairing, authenticated TLS, per-device credentials, revocation, bounded payloads, replay/idempotency handling, and rate limits.                          |
| Repository/filesystem → scanner | Explicitly selected roots, validated paths, symlink/traversal handling, bounded file sizes, format validation, and no script execution.                           |
| Coordinator → executable        | Allowlisted tool identity, argument arrays without shell interpolation, timeouts, bounded output, cancellation, and a controlled environment.                     |
| Coordinator → remote source     | Fixed/validated destinations, HTTPS, redirect policy, response limits, timeouts/backoff, and careful token scoping.                                               |
| Electron renderer → host        | Sandboxing, context isolation, Node integration disabled, narrow IPC if needed, navigation restrictions, and controlled external-link opening.                    |

LAN membership and Tailscale reachability are transport facts, not authorization. Hostnames and IP addresses are not device identities. Repository metadata, scanner output, and registry responses remain untrusted even when fetched over HTTPS.

## Read-only background monitoring

This PC package updates are separate explicit Windows desktop actions. Validated trusted-frame IPC accepts existing installation IDs and expected/target versions; fresh source/root/package checks reject changed, private, linked, unsupported, or stale targets. npm uses the observed prefix and Bun the observed global directory. The native runner locks each root, executes argument arrays without a shell, removes Node/Electron overrides, bounds runtime/output, cancels process trees, verifies installed metadata, and requests a rescan. Normal installer lifecycle/trust settings apply only to these owner-launched updates. Output is discarded and errors sanitized; no updater execution is exposed through HTTP, boot-host scheduling, or paired PCs. See [update behavior](global-tool-updates.md).

Owner-authored Project actions are a separate, manual Windows desktop capability. They run with the signed-in owner's privileges and can modify the checkout when launched. Saving/scanning never executes them. Trusted main-frame IPC validates schemas, selected project/action IDs, and the exact reviewed command; the native runner revalidates a canonical local directory and rejects provider-only/UNC targets. It uses an absolute allowlisted PowerShell executable, argument arrays with an encoded script, a separate cwd, no shell interpolation of project metadata, hidden windows, bounded output, a deadline, and process-tree cancellation. The environment removes inherited Electron/Node override variables. Quit UI stops tracked commands without stopping monitoring.

There is no command execution HTTP or paired-PC API. Shared evidence omits action definitions; output remains transient native memory and routine logs exclude command text/output. Commands are stored in owner-local SQLite without secret encryption, so avoid embedded credentials. The implementation follows [Node 24.19 child-process APIs](https://nodejs.org/download/release/v24.19.0/docs/api/child_process.html), [Electron sender validation](https://www.electronjs.org/docs/latest/tutorial/security#17-validate-the-sender-of-all-ipc-messages), [PowerShell EncodedCommand](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_powershell_exe?view=powershell-5.1), and [Windows process-tree termination](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/taskkill). See [command behavior and limits](project-settings.md).

Background work may inspect selected files and query documented metadata interfaces. It must not install dependencies, restore a project, execute lifecycle/build scripts, upgrade applications, modify lockfiles, or run arbitrary commands from repository configuration.

Some ecosystem commands have side effects. For example, `.NET package list` behavior depends on SDK version and may restore by default. Prefer existing resolved data; explicitly suppress restore only where that behavior is supported and verified. Missing data is an incomplete scan.

Local owner-session `outdated` checks run verified installed npm/pnpm CLI files through Node, or Bun's resolved executable, without a shell. Repository PATH entries and unverified CLI versions are skipped. Only eligible public direct names are passed as arguments. Each invocation has a 30-second deadline and 4 MiB output bound; stderr, malformed output, and unavailable records fall back without persisting raw output or paths. Inherited Node/Corepack/npm/pnpm overrides are cleared; npm user/global config files are isolated. pnpm hooks and automatic manager downloads are disabled explicitly, and configuration-dependency plugins cause file/registry fallback before CLI initialization. Noninteractive hosts and provider API scans never execute these commands. Live CLI verification checks that fixture manifests/lockfiles and the repository-script marker stay unchanged. Private registry authentication remains outside this feature. See [behavior and limits](package-manager-checks.md).

Project dependency changes, commits, and pull requests remain separate future user actions. This PC's explicit Update now action is implemented for supported global packages.

PC discovery selects installed npm/Bun executables from explicit absolute PATH entries and supported local Windows CLI fallback directories. npm's validated CLI runs through Node with fixed global root/config commands; `.cmd` shell wrappers are never executed. Bun runs only `--version`; its exact global directory is resolved from supported configuration/environment defaults without executing `bun pm ls`. That listing command can create its global directory and climb to an unrelated parent manifest when the expected manifest is absent. Commands run outside selected projects with argument arrays, timeouts, bounded output, and `NODE_OPTIONS` cleared. Package versions come from bounded installed manifests; package executables and lifecycle scripts never run. Canonical local roots and selected-file validation reject network shares, traversal, and escaping symlinks. The boot host reads owner-captured roots and Bun's single direct-dependency manifest; it grants no broad owner-profile or registry-credential access. Availability/version remains an owner-session observation after sign-out, separate from metadata access freshness.

Global lookup destinations are fixed to the public npm registry with HTTPS, rejected redirects, response limits, cancellation, and a scan budget. Public registry classification, excluded configured scopes, private manifest flags, and local/Git/URL dependency requests prevent known private/local names from public queries. Unknown registry/configuration evidence is not public permission. Source configuration is authenticated, schema/path validated, and cannot change during PC work. Refresh it after changing routing; background scans cannot observe new owner settings while signed out. Credentialed registries and complex unsupported Bun configuration need explicit support before checks can become verified.

## Data and secrets

Collect the minimum metadata needed to explain findings: package identities/versions, selected project/device identity, source/channel, scan provenance, and advisory references. Source code does not need to leave a device for ordinary dependency scanning. Advisory queries can reveal package names and versions to the selected provider; describe that egress when the integration is introduced.

Do not log tokens, credential-bearing URLs, raw lockfiles, source files, or full local paths by default. Sanitize errors and external process output. The transient coordinator capability is encrypted using Windows DPAPI LocalMachine in a private runtime descriptor so the owner and LocalService can reconnect. Scoped filesystem ACLs are essential: any account able to read that encrypted file on the same machine can potentially decrypt it. It is not an external registry credential and is not stored in SQLite or process arguments. Non-Windows descriptors rely on owner-only file permissions; native desktop behavior there is unverified.

`pnpm run access` deliberately prints that capability only on explicit owner request. The browser exchanges it for an HttpOnly, SameSite=Strict session cookie; Electron attaches a bearer capability in its native protocol handler. Host/origin checks, body/header limits, fixed API routes, and request/response schemas protect the loopback boundary. Restart rotates the capability and invalidates prior browser sessions. This does not protect against malicious processes already running as the owner or LocalService.

Public checks send eligible npm package identities and resolved versions to `api.osv.dev`; direct package names are queried from `registry.npmjs.org`. Source code, full local paths, lockfile contents, and registry credentials are not sent. Workspace/Git/local identities and private origins identified by selected-root `.npmrc` or lockfile URLs are excluded. User/global/ancestor/environment npm routing is not inspected; configure selected-root registry identity before scanning dependencies whose privacy depends on those settings. This ceiling is also reported in scan coverage.

Local database files and backups require appropriate filesystem permissions. Document retention, deletion, export, and credential revocation when persistence and enrollment ship. A remote collector must not receive the coordinator’s repository credentials.

## Meaning of vulnerability coverage

The initial intended scope is known dependency advisories, not a source-code audit, malware scan, or guarantee of safety. An absent advisory can mean no known match, unsupported identity, incomplete graph, stale data, or a failed lookup. Keep these outcomes distinct.

Use ecosystem/package identities and affected-version ranges. Installed desktop application names alone are insufficient for reliable CVE matching. Linux vendors backport fixes, so an old-looking upstream version is not by itself evidence of a vulnerable distribution package. Deduplicate advisory aliases while retaining each source’s evidence.

Use an explicit scanner version and report format coverage. Validate npm, Bun, NuGet, and Cargo behavior independently; support in an upstream tool does not mean support in Versionstead until the integration has been checked.

## Implementation gates

Before claiming a new boundary is supported, add focused checks for unauthorized or malformed input and the applicable failure cases. High-value cases include traversal/symlink escape, oversized inputs, subprocess timeout, offline lookup, revoked collector credentials, duplicate uploads, and interruption before a scan commits.

Before a public release, establish a license, a private vulnerability-reporting channel, dependency update policy, release signing, and a supported-platform matrix. This document is an implementation guide and capability limit, not a claim that a security audit has been completed.

## Implemented provider and paired-PC boundaries

GitHub.com and GitLab.com tokens and outgoing PC credentials are encrypted with Windows DPAPI LocalMachine in SQLite. The PFX/private key uses the same protection. Scoped filesystem ACLs remain essential: DPAPI machine scope permits the background service to unlock credentials, and anyone who can read the protected database on the same machine may be able to decrypt them. Provider connection never enumerates into the scan queue: only owner-selected repository IDs/refs are scanned. CLI token import is an explicit interactive action; the signed-out host does not read an owner CLI credential store. Disconnect deletes the current protected credential while preserving evidence. SQLite journal/backup retention can retain old encrypted blobs, so revoke the token with the provider when ending access.

Provider metadata/file requests use fixed HTTPS API hosts, reject redirects, have bounded responses and timeouts, and never execute fetched scripts. Every file request uses the commit resolved at scan start. Existing public npm/OSV classification still applies, including explicit unsupported/private coverage. Git status disables repository clean/process filters and fsmonitor, suppresses submodule checks, and clears inherited Git path overrides; a regression fixture configures executable filters and verifies that they never run.

PC sharing accepts private LAN/Tailscale IPv4 addresses, requires pinned TLS plus per-client bearer credentials, rejects browser-origin requests, and exposes no administrative API or arbitrary paths/commands. Pairing codes expire in five minutes, accept at most eight failed attempts, and are single-use. Clients validate the certificate before writing credential headers, then validate the device ID, response schema, and an unpredictable request nonce. Scan requests coalesce and are limited to once per ten seconds per client. Incoming JSON is limited to 4 KiB and received evidence to 16 MiB. The host allows 16 clients; this client supports eight connected PCs. Revocation immediately blocks new requests; an already completed read cannot be recalled. Removal attempts remote revocation, but an offline host requires the owner to revoke the client there too.

The self-signed certificate expires after one year. Certificate rotation and recovery UI, IPv6/DNS endpoints, central peer notification delivery, and physical two-PC/firewall/sign-out validation remain future work. TLS pinning prevents impersonation; it does not make an invitation from an untrusted source safe. Treat invitations as short-lived access secrets and exchange them through a trusted channel.

Pairing URLs put the encoded invitation in a fragment and validate it identically on the renderer and server. Separate host/code input cannot replace the invitation's endpoint or pin. Disabled environments retain evidence and protected credentials but stop polling and reject refresh/scan actions. Removing one still attempts remote revocation before forgetting its local credential.

Optional SSH forwarding runs only in an interactive owner session. The adapter reads at most 64 KiB/200 blocks of simple local SSH configuration as data; it never invokes `ssh -G` or evaluates Include/Match/proxy/executable directives. It passes validated host/user/ports and local key/known-host paths to the allowlisted OpenSSH client with an argument array, `-F none`, no remote command, loopback-only forwarding, strict host-key checks, batch authentication, and agent/X11 forwarding disabled. Native prompts and inherited Node/askpass configuration are disabled. Local key and known-host filenames containing SSH expansions, controls, quotes, or network-share paths are rejected. SSH stderr is discarded and bounded; connection attempts time out, and cancellation/disable/removal/shutdown terminate the tunnel.

The owner configures keys, an unlocked agent, and verified host keys separately. Versionstead stores no SSH passwords, private keys, or passphrases and does not install/start a remote SSH server or monitor. The HTTPS peer retains its original authority and certificate/device checks through the tunnel; credentials are sent only after its pin matches. This protects the Versionstead boundary independently of SSH host authentication. Real SSH authentication and physical remote networking remain acceptance tasks. Noninteractive hosts reject SSH transport and use authenticated LAN/Tailscale HTTPS instead.
