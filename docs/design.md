# Design and interaction

Versionstead should make evidence easy to understand and follow up. Use a compact, calm interface with semantic theme conventions. Avoid a marketing dashboard, decorative charts, or invented scan results.

## Present monitoring interface

The shared header provides native caption geometry, theme synchronization, and settings breadcrumbs. Settings uses compact icon navigation and searchable, focusable rows; it returns to the previous workspace rather than always opening Needs attention. Sidebar visibility is persistent. Device-default restoration is confirmed and limited to UI preferences and shortcuts.

The interface has four real workflows: Needs attention, This PC, Projects, and Background service. It separates connection health, scan freshness, coverage, update checks, and known-advisory results. Project selection, maintenance mode, manual scans, pause, schedules, and notification preferences invoke validated coordinator APIs. Host installation remains an explicit command with lifecycle verification, and Background service describes startup and sign-out for the coordinator host's own platform, each with a setup command and a Copy button: the Windows boot task from an elevated PowerShell, a macOS LaunchAgent that runs from login to logout, or a Linux systemd user service that runs before login and after logout only with lingering (the last two from `scripts/background-host.mjs`); any other platform says that monitoring after sign-out is not available yet, and the tray note appears only in the desktop app. Other platform-dependent copy follows the same rule: the folder placeholder uses the platform's path style, and wherever the desktop's command bridge is absent (a browser) custom commands say they run in the Versionstead desktop app. A planned feature belongs in documentation or clearly labeled explanatory text, not a button that appears functional.

A control waits only for its own request, including the read-back that follows it: requesting a scan, adding or removing a project, changing a project's maintenance intent, or saving a setting never disables the rest of the page. Needs attention's first-run Select project folders opens Add project directly.

The shared web/desktop interface offers System, Light, and Dark appearance. System follows `prefers-color-scheme`; explicit choices use local storage and survive restart within the same origin. The Electron renderer uses a stable `versionstead://app/` origin. Browser and desktop choices remain independent, and unavailable browser storage limits a choice to the current session. Native window chrome and OS integration still require platform-specific visual verification.

The approved design is implemented with source-owned shadcn Base UI components, using the `base-mira` configuration. An integrated 40 px Windows caption (52 px browser header) and 205 px collapsible sidebar frame the workspace. Shared buttons, badges, selectors, collapsibles, tables, evidence sheets, and toasts use semantic tokens. The existing Versionstead V mark is shared by the title bar and update panel, with corresponding favicon, native window, tray, and notification icons. Appearance preview cards, paired palette orbs, interface sliders, motion preview, and typography previews are shared components. Third-party MIT notices are in [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md).

## Information hierarchy

The four monitoring destinations now share a sidebar utility area with Settings and Update controls. Settings has General, Appearance, Keybindings, Source Control, Connections, and Project routes. Paired computers appear as separate evidence destinations. Scan history stays in Background service; update, advisory, and lifecycle filters stay in Needs attention. Introduce further destinations only when they have useful content and a real workflow.

A finding should answer, in order:

1. What is affected?
2. What changed or was detected?
3. How recent and complete is the evidence?
4. What source supports the conclusion?
5. What action is available?

Use tables for comparable package data, a focused details panel for evidence, and short readable empty/error states. Group a shared advisory across affected subjects without hiding their different scan times or versions.

Needs attention groups findings by stable PC/project identity; URL filters for update and advisory summaries remain effective. Failed, partial, unsupported, and unscanned targets appear in All findings and Incomplete checks, even without a package finding. Counts distinguish package observations, updates, advisories, lifecycle findings, and incomplete checks; All findings totals those same deduplicated units plus any Other findings. Summary counts combine repeated project workspaces; dependency rows preserve their own requested ranges and resolved versions, and PC findings remain distinct by manager, while a global tool's update and deprecation count as one package, and so does the same tool in two global locations of one manager (each location's own findings are still counted). Finding rows sort by severity, then name; an unknown severity ranks above low, so unassessed risk is never buried beneath it.

Snoozed & ignored lists the findings a rule hides, each with its rule ("Snoozed until Nov 7", "Snoozed until a version newer than 2.1.0", or "Ignored: {reason}"). Hidden findings leave the Needs attention counts, the Projects summary, the sidebar badge, and notifications; an empty view says how many findings are hidden. A snoozed incomplete check takes its target out of the incomplete count and out of Incomplete checks, and out of All findings unless other findings keep it there; the target keeps its Partial or Failed status everywhere, and its notice keeps listing its errors. A connected PC's hidden findings stay out of its lists and counts and are reviewed on that PC. Projects keeps showing full evidence for each project, including hidden findings. Each Needs attention finding row's menu offers Snooze 7, 30, or 90 days, Snooze until a version newer than the candidate (updates with a SemVer candidate), and Ignore… with a required reason of 3 to 200 characters; incomplete checks can be snoozed but not ignored. Hidden rows offer Unsnooze, or Stop ignoring for an ignored finding. A rule covers one package's updates, or one advisory, deprecation notice, or incomplete check, in one PC or project, so it also hides the same package in the project's other workspaces. A snooze follows a package across new candidates until its date or version, but an advisory with another identity or a higher rating, an incomplete check with different errors, a lifecycle finding whose severity rises, or a candidate newer than a version snooze appears again. A rule is also removed once it hides nothing: when its date passes, a newer candidate or a higher rating appears, the finding is resolved, or its target is removed.

Times read as ages in whole units ("5 minutes ago", "1 day ago", "in 2 hours"; never "yesterday", which is wrong by a day after 24 to 47 hours) with the exact local time as a tooltip, and stay current without a refresh. A target whose last success is older than twice its scan interval, whether or not scanning is paused, also carries a Stale badge in its Needs attention or Projects group header and in the This PC summary; a target that never succeeded does not. Each Needs attention finding row and Projects dependency row has a menu: Copy upgrade command, Copy package name when no command applies, Open on npm, Open advisory, Open repository (provider projects), and Copy path (local projects); Needs attention rows also offer the snooze and ignore actions above. A command is built only for a registry, non-alias, non-transitive dependency with a checked candidate, at that exact version, once per workspace holding the package, and only for the owner to run; Versionstead never runs it. An advisory is offered an update only when it reaches the advisory's listed fixed version, and none when no fixed version is listed; a This PC command is withheld while the PC's update results are unverified or in flux. Needs attention and Projects offer Expand all and Collapse all, and their collapsed groups stay in the page (`hidden="until-found"`) so browser find opens them. Each Projects group with dependencies also offers Upgrade commands: one copyable command per workspace and dependency type (the save flag applies to a whole command), compatible updates only by default and every checked update when Include major updates is on, plus Copy all. Aliases, unquotable workspace paths, a package manager Versionstead has no command for, unchecked candidates, snoozed or ignored packages, and releases younger than the release cooldown (the age is known for the release an update finding describes) are left out and counted: the dialog says how many packages could not be checked and never reads as "no updates" while any could not be, and it states how old the project's last successful scan is and when the latest scan failed or is unsupported. Versionstead never runs these commands. Export (Needs attention, This PC, Projects) builds Markdown for an issue or pull request, CSV, or JSON for This PC, one project, or This PC and all projects from the evidence this window holds (a paired computer's evidence is reviewed on its own page and is not included), and copies it or saves a file. A copy reports its result in the dialog, which stays open, and leaves out the byte order mark a saved CSV file carries; the title and file name read "This PC and all projects" for the widest scope, and projects that share a name are numbered. Every export names each target's status, last successful scan, latest attempt, coverage, and incomplete checks, and includes snoozed and ignored findings with their rule. Markdown and JSON also say that a missing finding on an incomplete target is not evidence of safety and mark the findings of a Failed or Unsupported target as previous and unverified; CSV repeats each target's status and incomplete checks on every row and gives a target without findings a row of its own. Markdown escapes its syntax, but GitHub may still turn bare web addresses, email addresses, @handles, and issue numbers in advisory or deprecation text into links, so the dialog asks the owner to read an export before sharing it.

Projects initially shows selected folders with findings, incomplete evidence, failed checks, or active/queued scans. All projects restores the complete selected-folder list. Each expandable group initially shows dependencies needing attention; All dependencies exposes retained inventory and source exclusions. A project's runtime lifecycle findings have no dependency row, so its group lists them above its dependencies in a Runtime support notice that links to the Lifecycle filter in Needs attention. Intentional transitive version exclusions alone do not classify a complete project as needing attention. Search filters targets and package rows. Dependency, finding, and global-tool tables render 200 rows at a time; Show more reveals the next rows and focuses the first of them, and a filter or search change starts again from the first page. Expansion choices survive snapshot refreshes, and header scan actions sit outside the disclosure button. Add, remove, maintenance mode, and scan actions use the existing validated APIs. Version drift, a third Projects tab, lists direct registry packages resolved at different versions across selected projects and their workspaces, and npm and Bun copies of one global tool at different versions, with the version to align to (the newest stable version in use, or the newest prerelease when no stable version is in use), every version in use, and how many copies are behind it. A package opens its version matrix, with the copies that need a change first: each copy, its version and update-kind badge, and a copyable command that moves a copy that is behind to the version to align to (none for aliases or other sources; a copy at or newer than it, such as a prerelease, is left as it is). A This PC command is withheld while the PC's update results are unverified or in flux, or the coordinator cannot be reached. The matrix says that versions come from each target's latest collected evidence, that a target that failed or was never scanned may be out of date, and that a partial PC scan keeps the copies from an earlier scan for any global location it could not read. Only SemVer versions from collected evidence are compared; the view is computed in the window and creates no findings or notifications.

Needs attention adds New since last scan, which lists findings first detected after their target's previous successful scan (a target last scanned by an older build starts comparing at its next success), and Resolved, which lists for 30 days what a later successful check stopped reporting and when. Resolved lists this PC's own history, recorded from this version's first scan of each target; a connected PC keeps its own, so Needs attention shows no Connected PCs section on that tab, as on Snoozed & ignored. Retry failed checks (N) beside Scan now rescans every target whose status is Failed or Partial. A target that stays Partial for a reason a rescan cannot change keeps the button visible; Unsupported targets are not retried (Scan now on the project picks up a fix). While a scan runs, its progress card offers Cancel scan until it has finished its package and advisory checks and starts writing results; a cancelled attempt reads Cancelled in Scan history and the target keeps its previous evidence.

Needs attention and Projects start with every accordion closed on entry. Expanding one group does not close another; manual choices survive snapshot refreshes and filter changes while that page remains mounted. Evidence panels and scan buttons keep their separate interactions.

## Theme and component rules

- Use semantic CSS variables for canvas, surfaces, text, muted text, borders, focus, and status colors.
- Support light, dark, and system preferences when theme selection is exposed; persist the explicit preference locally. The stylesheet's defaults are the default palette (`light-dark()`, following the system), and the stored theme is applied before React's first render (a script in the page would break the CSP, so the page can still paint the defaults for the moment before the bundle runs).
- Give meaning its own token instead of borrowing the accent. Link text (`--link`), a control's boundary (`--control-border`), and success (`--success`) are tokens derived from the chosen palette or fixed per theme, so text keeps 4.5:1 and a boundary or switch state 3:1 on every surface in both default themes. Dialogs, drawers, and popups are translucent glass over a dimmed page, so they use a stronger muted text (`--muted-glass`). `contrast.test.ts` checks the shipped pairs, and a custom theme gets the same derivation.
- Centralize component variants rather than adding slightly different buttons and badges on each page.
- Use readable typography, aligned tabular version data, restrained borders, and enough space for long package names and paths.
- Keep dense tables horizontally usable and provide a sensible narrow-window layout. Desktop does not imply a fixed viewport.
- Use the shared shadcn/Base UI primitives for the approved interactions. Native form dialogs remain accessible; avoid another component dependency when the existing control meets the need.

## Accessibility and behavior

Use semantic landmarks, properly labeled controls, logical heading levels, visible keyboard focus, and sufficient contrast in both themes. Do not remove browser keyboard behavior without a clear replacement. Honor reduced motion and avoid unnecessary animation: spinners stop under the system or in-app setting.

A route change sets the page title to "Page · Versionstead" and moves focus to the content region; the first load does not move focus, and a link to a single setting focuses that setting instead. A dialog opened from a menu item returns focus to that menu's button, and a row that leaves its list while its menu button has focus (a snoozed or ignored finding) hands focus to the content region instead of dropping it. A button's accessible name includes the text it shows ("Scan now: versionstead", "Change shortcut for Open settings, currently Ctrl+,"), and a control repeated on every row is named for its row ("Actions for lodash 4.17.21 in root"), numbered "(2 of 3)" only where that name repeats. Evidence and empty states take the heading level their place calls for (3 inside a group, panel, or drawer), and the sidebar's device name is not a heading. Scan progress is one persistent status line that announces stage changes and results, while its counts and elapsed time stay silent; a pairing link's countdown is not a live region and only its expiry is announced.

Async actions show progress and a meaningful failure state. Keep prior content while refreshing it. Cancellation, retry, and destructive actions need accurate labels. Hard-to-undo actions ask first: removing a project or environment, revoking a paired client's access, disconnecting a provider, restoring device defaults, and resetting all shortcuts. Never show “updated” or “secure” solely because a request was submitted.

This PC begins with an empty Scan this PC prompt. npm and Bun have independent detection/version cards with expandable configured global locations and owner-source timestamps. After scanning, Updates available is the default filter; All global tools, Up to date, and Unverified expose other observations. A package-manager filter selects npm, Bun, or both. Unknown available-version/update cells remain blank with a single coverage explanation. A browser cannot run installers, so each update row offers Copy command (the generic `npm install --global` or `bun add --global` command at the exact version) beside one note that updates run in the Versionstead desktop app; no disabled Update now buttons remain there, and an inactive button (Update now on the desktop, Copy command in a browser, while the PC's results are unverified or a scan runs) stays focusable with its reason. No candidates, unavailable checks, failed checks, and an empty search each have distinct messages. On the desktop, Update all (N) asks first, listing every package and its version change: releases younger than the release cooldown and updates you snoozed or ignored (shown with their rule) start unticked, releases with no known release time are listed on their own, and Major updates carry their badge. While it runs, its panel shows each package's state and ends with a summary; Stop takes effect after the current package finishes and does not cancel an install already running; and the row buttons say Update all is running.

One shared scan progress control shows the active target/stage, measured stage-local counts when known, queued targets, and terminal outcome/elapsed time. Unknown totals remain indeterminate; disconnected information freezes with a last-observed label. A completed stage does not imply complete coverage.

Notifications show one count summary after a scan cycle settles, combine the signed-out backlog, and use a persisted five-minute cooldown. Unchanged findings stay quiet. Update and security-advisory counts remain distinct, and a summary click opens the appropriate Needs attention filter. Notify about chooses all updates and advisories (the default), advisories only, or high and critical advisories, which also takes advisories without a rating because a missing rating is not evidence of safety; watch-only projects notify only when Notify about watch-only projects is on, and both apply only while Notify about new findings is on. Snoozed and ignored findings, incomplete checks, and lifecycle findings never notify. Quiet hours (a local window that may cross midnight) hold native notifications until the window ends, while in-app summaries still appear. Notification delivery is after each scan cycle or a daily digest at a chosen local time that combines everything new since the last digest; a digest missed while the PC slept arrives when monitoring next runs. Times use native time inputs and save when a field loses focus; an empty time, or a quiet-hours start equal to its end, is put back to the saved value.

One app-wide shadcn/Base UI toaster presents these summaries, successful actions, and failed actions; a lost connection is reported only by its banner. A failed action is reported once: as a toast, or beside the form that owns it. A toast sits outside a modal dialog, where it is inert and unannounced, so every dialog that asks the coordinator for something (Add project, Connect provider, Disconnect, Revoke access, Remove, Ignore, Network access, pairing links, project icon and actions) shows the real reason inline and cannot be dismissed while its request runs, and every dialog that copies (Upgrade commands, Export) says the result in a status line it keeps mounted, because a live region announces a change in its text, not its arrival; a message that arrives after its form has closed falls back to a toast. It never also becomes a banner, and a dialog opened later never shows it. A summary offers Review and Close; its opaque identity is saved in a bounded 200-entry device-local history so polling, native delivery, and reloads do not replay it. Routine status polling produces no success toast. At most three toasts remain visible in the stack. Toasts support keyboard dismissal, F6 focus, hover/focus pause, swipe dismissal, reduced motion, and narrow windows. Persistent banners are for the connection and for compatibility. The Disconnected banner can be dismissed until the connection is next lost, the older-build banner until that coordinator restarts (PC scan controls still say for themselves when the collector is too old), and the access-code prompt offers a Copy button for `pnpm run access` and reports a refused code only after one is submitted. Native OS notifications retain their existing receipt behavior when the UI is hidden.

The command palette (Ctrl+K, ⌘K on macOS, rebindable) is a modal dialog with a combobox over one listbox: arrow keys move the active option through aria-activedescendant, Enter runs it, Escape clears the search, then closes it and returns focus, and keys pressed during IME composition stay with the composition. It does not open over another dialog, and a dialog one of its actions opens (Add project, Export) appears after it closes, so closing that dialog returns focus to where the palette was opened. Enter waits while the list is still catching up with the typed text, the highlight stays on its option when the list refreshes (a Cancel scan option names its scan), a hidden line says how many options there are, projects with the same name are numbered, and a host too old to run Scan this PC or Scan all sources does not list them.

## Settings

Project provides a project/environment selector, Name/icon group, icon picker, Actions editor/list, and Danger confirmation. Name commits on blur/Enter, icons reset to an automatic monogram, action edits preserve identity/order, and removal leaves files untouched. The scope hint describes actual local/paired permissions; other settings pages remain global. Custom commands launch manually from a review/output dialog or project-scoped shortcut; there are no thread, bootstrap, or worktree options. Glyph selection uses a curated 24-icon catalog alongside emoji, monogram, and uploaded images. See [Project settings](project-settings.md).

Settings uses narrow icon navigation, grouped bordered rows, muted section labels, inline tool versions/status indicators, compact switches, and a sidebar utility area. Source Control uses provider/VCS SVGs in a discovery-row layout: status dots overlap the icon, CLI versions sit beside the name, and chevrons reveal Git context and provider connection/selection details. The repository switch and interval control use existing scan preferences; unsupported VCS/providers say Coming soon. The release sheet distinguishes checking, available, current, unpublished, and failed; an unpublished release is never presented as a verified current build.

Appearance controls live only in Settings. Three mode previews and six built-in palette pairs use wireframe previews and palette orbs. Light/dark palettes can be selected independently; custom-theme create, duplicate, edit, import, and remove actions are functional. Contrast, glass opacity, content width, panel duration, fonts, font sizes, word wrap, density, and reduced motion update real interface tokens. Advanced typography supports table and evidence-panel size overrides. Shortcut capture rejects conflicts, supports disable/reset, never traps focus (Tab, Shift+Tab, and Escape behave as usual in a capture field), and does not intercept typing or dialogs. Shortcuts read ⇧⌘S on macOS (Control, Option, Shift, Command, as Apple orders them) and Ctrl+Shift+S elsewhere. With Ctrl, Alt, or Command held, a key that does not type an ASCII letter or digit is matched by its physical position, so Option+S on a Mac (it types ß), AltGr combinations, and non-Latin layouts still reach the S shortcut; a key that does type one is matched by what it types, so Colemak and Dvorak follow their printed keys. Shift does not count on a bare digit or symbol, so `/` works on layouts that type it with Shift, and a shortcut saved as shift+/ before that is read as `/`. Appearance and Keybindings read device-local storage, so they render before the coordinator's settings arrive; the other settings pages wait for them. The PC evidence view keeps remote timestamps, coverage, failure state, and received data separate from local editing controls, and says it is loading rather than that a PC is missing until the coordinator's settings arrive. Once they are in, it says "Loading evidence" while a PC's received data is being read, "Evidence could not be read" with Retry when that read fails, and "No evidence received" only for a PC that has sent nothing. Evidence held from an earlier receipt is labeled as earlier while the latest is read or after its read failed (with Retry), so it never sits unqualified beside a newer "Last received" time; Needs attention and the sidebar count list a PC whose latest evidence could not be read. A failed read runs again on Retry or when newer evidence arrives.

Source Control has a deterministic redacted account placeholder, click-to-reveal tooltip, refresh icon, and visibility/reduced-motion handling. Refresh has its own pending state and revalidates stored provider authentication without scanning repositories or emitting the general mutation notice. Existing connection evidence survives a failed check.

Add Project has a searchable source chooser, setup-required route, repository list, back navigation, and confirmation flow. Local folders use the native picker; GitHub/GitLab and their HTTPS/SSH URLs identify accessible repositories for read-only API monitoring. Confirmation exposes the branch/ref and maintenance intent. No repository becomes a selected project before confirmation. The same picker serves Source Control and Projects.

Connections has grouped machine rows, overflow menu, compact Environments heading, saved rows, and centered empty state. Add Environment uses the same Remote link/SSH cards, highlighted selection, host/code and username/port layout, and blurred backdrop. Full pairing links populate both remote fields; codes remain concealed. Inline errors and a pending action keep the dialog open until pairing succeeds. SSH adds an explicit monitor-invitation verification step because Versionstead connects an existing monitor instead of bootstrapping an agent.

Machine/environment actions use shared Base UI menus. Environment switches pause polling without removing retained evidence; removal confirms its revocation effect. Network access and pairing dialogs reuse the native Dialog wrapper, with Select popups portaled into its top layer. Accent/error tokens, keyboard focus, Escape, restored trigger focus, and stacked narrow-window fields follow the shared theme and control behavior. Local rows expose real scan, release, sharing, Tailscale-address, and host-mode state; there are no agent controls. Where a macOS or Linux host has no usable keychain (a Mac without its login keychain, or a Linux host with no unlocked Secret Service keyring), Network access, Tailscale setup, and Add environment stay off, and the page shows the reason the coordinator reports, as Source Control does. Windows needs no such check; a policy that blocks DPAPI (Constrained Language Mode) surfaces as an error when monitoring starts or a credential is stored, not as disabled controls.
